# Agentic AI Skills Security Best Practices

This framework provides security guidance for designing, reviewing, deploying, and operating agentic AI skills. Its controls, checklists, templates, examples, response guidance, and adoption roadmaps are organized into the following chapters.

## Chapters

1. [System definition and boundaries](01-system-definition-and-boundaries.md) — Defines agentic skills, scope, trust boundaries, architecture, actors, data, and credentials.
2. [Lifecycle model and security gates](02-lifecycle-model-and-security-gates.md) — Maps security gates and material-change triggers across the skill lifecycle.
3. [Threat model](03-threat-model.md) — Identifies assets, threat actors, entry points, abuse paths, assumptions, and authority-amplification risks.
4. [Risk tiering and control profiles](04-risk-tiering-and-control-profiles.md) — Classifies skill risk and maps tiers to appropriate control profiles.
5. [Security best practices and control catalog](05-security-best-practices-and-control-catalog.md) — Provides the core controls for design, supply chain, permissions, execution, testing, operations, and governance.
6. [Role-specific implementation checklists](06-role-specific-implementation-checklists.md) — Organizes implementation actions for creators, administrators, platform teams, security teams, and governance functions.
7. [Intake, review, approval, and exception templates](07-intake-review-approval-and-exception-templates.md) — Supplies reusable governance forms, approval criteria, hard stops, and exception records.
8. [Illustrative implementation examples](08-illustrative-implementation-examples.md) — Shows safer instructions, permission declarations, approval prompts, audit events, and release checks.
9. [Worked hypothetical scenarios](09-worked-hypothetical-scenarios.md) — Applies the framework to malicious skills, poisoned instructions, excessive permissions, compromised updates, and cross-skill attacks.
10. [Incident response playbook](10-incident-response-playbook.md) — Covers triage, containment, investigation, recovery, notification, and lessons learned.
11. [Maturity model and metrics](11-maturity-model-and-metrics.md) — Defines maturity levels and measurements for tracking security-program effectiveness.
12. [Prioritized 30/60/90-day adoption roadmaps](12-30-60-90-day-adoption-roadmaps.md) — Provides phased implementation plans for small teams and large enterprises.
13. [Sources](13-sources.md) — Consolidates OWASP, NIST, protocol, supply-chain, secure-design, and platform references.

Start with [Chapter 5](05-security-best-practices-and-control-catalog.md) for the core best practices, or [Chapter 12](12-30-60-90-day-adoption-roadmaps.md) for a phased adoption plan.
